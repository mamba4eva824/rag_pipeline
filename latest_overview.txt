## 1. System Overview

This RAG (Retrieval-Augmented Generation) system provides intelligent access to Confluence knowledge base content through a Slack bot interface. 
The system combines vector search, semantic retrieval, and OpenAI's language models to deliver accurate, contextual responses to user queries.

**Core Capabilities:**
- Semantic search across Confluence documents
- Real-time Slack bot interaction
- Intelligent synonym handling
- Source attribution with clickable references
- Clean, professional response formatting
- Comprehensive logging and debugging

**Technology Stack:**
- Vector Database: Pinecone
- Embeddings: SentenceTransformer (all-MiniLM-L6-v2)
- Language Model: OpenAI GPT-4o-mini
- Framework: LangChain + Slack Bolt
- Interface: Slack Bot (mentions, slash commands, DMs)

## 2. Architecture Components

### 2.1 Retrieval Layer (`retreiver/retrieval.py`)
**Purpose:** Handles vector search and document retrieval from Pinecone

**Key Classes:**
- `ConfluenceRetriever`: Main retrieval interface
- `SentenceTransformerEmbeddingsWrapper`: LangChain compatibility layer

**Features:**
- Multiple search methods (LangChain, hybrid, legacy)
- SentenceTransformer embedding model integration
- Pinecone vector database connection
- Configurable top-k retrieval (default: 5 documents)
- Metadata preservation and formatting

**Search Methods:**
1. **LangChain Search** (default): Uses PineconeVectorStore with similarity_search_with_score
2. **Hybrid Search**: Attempts advanced retrieval methods if available
3. **Legacy Search**: Direct Pinecone API for backward compatibility

### 2.2 AI Integration Layer (`retreiver/openai_assistant.py`)
**Purpose:** Manages OpenAI interactions and response generation

**Key Classes:**
- `OpenAIAssistant`: Main AI interface with context management

**Features:**
- System prompt optimization for company knowledge base
- Context formatting for multiple document sources
- Response streaming support
- Comprehensive logging and timing metrics
- Temperature and token control

**System Prompt Design:**
- Restricts responses to provided context only
- Eliminates generic date/URL statements
- Focuses on clear, direct answers
- Separates content from source attribution

### 2.3 Slack Interface Layer (`retreiver/slack.py`)
**Purpose:** Provides user-friendly Slack bot interface

**Key Features:**
- Multiple interaction methods (mentions, slash commands, DMs)
- Query preprocessing with synonym expansion
- Professional response formatting with structured blocks
- Source attribution footer with clickable references
- Error handling and user feedback

**Synonym System:**
- Maps related terms: owner ↔ admin ↔ administrator ↔ approver ↔ responsible ↔ contact
- Expands queries for better semantic matching
- Improves consistency across similar queries

## 3. Data Flow

### 3.1 Query Processing Pipeline
```
User Query (Slack)
    ↓
Query Preprocessing (synonym expansion)
    ↓
Vector Embedding (SentenceTransformer)
    ↓
Semantic Search (Pinecone + LangChain)
    ↓
Context Formatting (multiple documents)
    ↓
AI Response Generation (OpenAI GPT)
    ↓
Response Formatting (Slack blocks)
    ↓
User Response (with footer attribution)
```

### 3.2 Detailed Flow Steps

1. **Input Processing:**
   - Receive query via Slack (mention/@shelby, /shelby command, or DM)
   - Clean and preprocess query text
   - Apply synonym expansion for better matching

2. **Retrieval Phase:**
   - Convert query to vector using SentenceTransformer
   - Search Pinecone index for top-5 most relevant documents
   - Return documents with similarity scores and metadata

3. **Context Preparation:**
   - Format retrieved documents for OpenAI consumption
   - Include titles, content, metadata, and relevance scores
   - Preserve source information for attribution

4. **AI Generation:**
   - Send formatted context to OpenAI GPT-4o-mini
   - Apply company-specific system prompt
   - Generate focused, contextual response

5. **Response Delivery:**
   - Format response in Slack blocks
   - Add structured footer with source attribution
   - Include clickable document references
   - Display timing information

### 6.2 Model Configuration
```python

model_name="gpt-4o-mini"      # Fast, cost-effective model
max_tokens=1500               # Response length limit
top_k=5                       # Documents per query
temperature=0.0               # Deterministic responses

# Embedding Model
MODEL_NAME="all-MiniLM-L6-v2" # SentenceTransformer model
```

### 6.3 Pinecone Configuration
```python
# Vector Database Settings
DEFAULT_INDEX_NAME="hit-confluence"
DEFAULT_TOP_K=5
```

## 8. Technical Details

### 8.1 Vector Search Configuration
- **Embedding Dimension:** 384 (all-MiniLM-L6-v2)
- **Similarity Metric:** Cosine similarity
- **Index Type:** Pinecone standard index
- **Chunk Size:** 1000 characters with 100 character overlap

### 8.2 AI Response Parameters
- **Model:** gpt-4o-mini (optimized for speed and cost)
- **Temperature:** 0.0 (deterministic responses)
- **Max Tokens:** 1500 (comprehensive but concise)
- **Context Window:** ~3000 tokens including system prompt

### 8.3 Slack Integration Architecture
- **Connection Method:** Socket Mode (real-time)
- **Response Format:** Slack Block Kit for rich formatting
- **Threading:** Asynchronous processing to avoid timeouts
- **Error Handling:** Graceful degradation with user feedback

## 9. Troubleshooting

### 9.1 Common Issues

**No Results Found:**
- Check if documents exist in Pinecone index
- Verify embedding model matches ingestion model
- Try different query phrasings

**Slow Responses:**
- Monitor OpenAI API rate limits
- Check Pinecone query performance
- Review network connectivity

**Inaccurate Responses:**
- Verify system prompt configuration
- Check document quality in knowledge base
- Review retrieval relevance scores in logs

### 9.2 Logging Locations
```
logs/slack_bot_YYYYMMDD.log          # Slack interactions
logs/openai_interactions_YYYYMMDD.log # AI responses
```

### 9.3 Performance Monitoring
- **Query Processing Time:** Typically 1-3 seconds
- **Retrieval Phase:** ~0.5-1.0 seconds
- **AI Generation:** ~1.0-2.0 seconds
- **Slack Delivery:** ~0.1-0.3 seconds
